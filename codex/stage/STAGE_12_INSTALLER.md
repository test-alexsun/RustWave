## Задания этого этапа

### Задача
Создай установку RustWave одной командой на Debian 13 **с реальным выбором БД и режима развёртывания**. Реализуй идемпотентное обновление, бэкап, восстановление и миграции без потери данных.

### Выполнение
1. Разработай `install.sh` и, если оправдано, Rust CLI. Главные действия: `Install`, `Update`, `Backup`, `Restore`, `Migrate DB`, `Status`, `Diagnostics`, `Uninstall` (последний без удаления данных по умолчанию).
2. Интерактивный выбор **1 SQLite / 2 PostgreSQL**. Для PostgreSQL выбор `local PostgreSQL / Docker PostgreSQL / external PostgreSQL`; validate host/port/user/DB/TLS, пароли вводи безопасно. В SQLite режиме **не запускать, не устанавливать и не требовать PostgreSQL**.
3. Далее выбор **1 Native systemd / 2 Docker Compose**. Для SQLite — persistent file и WAL, при Docker volume bind path, `read_only` root FS и непривилегированный UID. Для PG — отдельный контейнер только если выбран Docker PG; не открывай DB порт наружу без причины.
4. Предусмотри `--db sqlite|postgres --mode native|docker --non-interactive --config <file>` и безопасные ошибки при нехватке параметров. Сохрани текущие настройки APP_PORT=3000, METRICS_PORT=3001 по умолчанию; проверяй занятость портов и не заменяй существующий сервис.
5. Backup/restore SQLite (WAL-aware) и PG (`pg_dump`/`pg_restore`), checksum/verify, transactional/dry-run migrations и сценарий замены GoWave только **на копии**. Переезд Go→Rust не меняет UUID, секреты, токены, ссылки подписок. Переключение production — только по отдельному подтверждению пользователя.
6. Не используй `curl | bash` без явной проверки происхождения и контрольных сумм скриптов/бинарников. Проверяй архитектуру, версию Debian, RAM/disk, подписи/checksums, права, SELinux/AppArmor при необходимости. При ошибке — понятный rollback без уничтожения данных.
7. Прогони автоматизированные тесты установщика для 2 БД × 2 режимов, плюс PG external конфигурация, повторный запуск, update и rollback. На VPS только в изоляции и без захвата существующих портов.

8. После установки проверь не только API health, но и загрузку **того же React frontend**, GET/HEAD static/SPA/gzip, отдельный metrics listener с enable/disable/auth; сравни с Go эталоном. Режимы SQLite/PG × native/Docker должны исполнять соответствующие smoke-IDs без skipped/ignored. Не выдавай за успешную установку контейнер с HTTP 200 на health, но сломанными статическими ресурсами.
