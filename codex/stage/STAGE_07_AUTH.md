## Задания этого этапа

### Задача
Полностью воспроизведи auth и security behavior исходного GoWave, не ослабляя проверки ради лёгкого backend.

### Выполнение
1. Изучи `internal/auth`, `internal/middleware`, `internal/tokens`, `internal/stubs` (passkey/OAuth), `internal/contracts/scopes`, `go-webauthn`, JWT и cookies в эталонном Go; составь набор endpoint×role×token×scope.
2. Перенеси login/register/status/logout где реализован, JWT generation/validation, claims, expiry, HMAC/alg checks, API tokens, token scopes, cookie settings, CORS, CSRF-поведение, passkeys/WebAuthn, OAuth2/Telegram auth, rate limit — только то, что действительно есть в upstream, без выдуманных компонентов.
3. Пароли и ключи из GoWave должны оставаться рабочими при Rust переходе: сравни алгоритмы хеширования/верификации, lifetime, encoding и ошибки. Не записывай секреты в логи.
4. Для обоих БД проведи differential tests на valid/invalid/expired/revoked tokens, 401/403, privilege escalation, scope boundary, missing fields, cookies, CORS, replay and malformed payloads.
5. Сопоставь JSON envelope, timestamp/path/errorCode и response statuses; избегай N+1 запросов и лишних crypto allocations, но сначала добейся parity.

6. Добавь потребительские frontend-auth shape tests для login/status/401/403, cookie/session и token scopes с неизменённым React и обеими DB. Проверь отсутствие/null/empty и error envelope, авторизационные редиректы и загрузку UI после истечения сессии. Используй controlled clock; не пропускай обязательные negative cases.
